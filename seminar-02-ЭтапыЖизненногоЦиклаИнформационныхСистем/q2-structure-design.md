# Конспект: Анализ требований и проектирование структуры ИС

## Ключевые этапы разработки информационной системы

### Введение
Качество анализа требований и проектирования структуры определяет успех создания ИС, влияя на:
- Функциональность
- Надежность  
- Соответствие потребностям заказчика

## 1. Анализ требований

**Цель**: Определение функционального назначения системы через документирование потребностей пользователей и заказчика.

**Этапы процесса**:
- **Сбор требований**
  - Интервью с стейкхолдерами
  - Анализ документации
  - Опросы и анкетирование
  - Наблюдение за пользователями
  - Работа с фокус-группами

- **Анализ и классификация**
  - Функциональные требования (конкретные операции)
  - Нефункциональные требования (производительность, безопасность, надежность)

- **Формирование документации**
  - Техническое задание
  - Спецификация требований (SRS)

## 2. Проектирование структуры

**Цель**: Создание архитектуры системы, отвечающей установленным требованиям.

**Основные аспекты**:

### Архитектурное проектирование
- Выбор архитектурного стиля
- Определение компонентов системы
- Распределение по уровням

### Проектирование данных
- Разработка моделей БД
- Нормализация данных
- Оптимизация запросов

### Детальное проектирование компонентов
- Интерфейсы компонентов
- Алгоритмы и бизнес-логика
- Форматы данных

### Проектирование UI/UX
- Макеты интерфейсов
- Навигационные схемы
- Сценарии взаимодействия

**Результат**: Пакет проектной документации включающий:
- Архитектурные диаграммы
- Схемы БД
- Спецификации API
- Прототипы интерфейсов

## 1. Системы управления требованиями (Requirements Management Tools)

### Корпоративные решения
- **IBM Engineering Requirements Management DOORS**
- **Jama Connect**
- **Modern Requirements** (интеграция с Azure DevOps)

## 2. ALM-платформы (Application Lifecycle Management)

### Комплексные решения
- **Azure DevOps Server** (ранее TFS)
- **IBM Engineering Lifecycle Management**
- **Polarion ALM**

## 3. Специализированные инструменты для аналитиков

### Инструменты моделирования
- **Enterprise Architect**
- **IBM Rational Rhapsody**
- **Visure Requirements**

## 4. Универсальные инструменты с функционалом для требований

### Гибкие решения
- **Jira** + дополнения (Requirements Management for Jira)
- **Confluence** - для документирования требований
- **Microsoft Word** + средства контроля изменений

## 5. Облачные и гибридные решения

### SaaS-платформы
- **IBM DOORS Next**
- **Jama Connect**
- **Valispace** (для инженерных требований)

## Заключение

Анализ требований и проектирование структуры - взаимосвязанные критически важные этапы. 

**Ключевые преимущества качественного выполнения**:
- Предотвращение роста затрат
- Обеспечение соответствия ожиданиям пользователей
- Успешная реализация ИТ-проекта
